## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell chrome -> user’s first impression | over-weight shell modules can make the product feel like a generic AI control room before the task surface is even noticed |
| context-lane visibility -> task comprehension | a permanently visible right rail can imply false precision/system importance and pull attention away from ROI/export/review work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | D | `TopBar.js` / `ProcessRail.js` / `layout.css` | mitigate | reduce shell density and preserve stage dominance so support chrome cannot compete with the actual task surface |
| T-06-04 | I | `ContextLane.js` / `App.js` | mitigate | keep the lane selection-driven and hidden for ROI/export so generic utility modules cannot misrepresent what matters on each step |
</threat_model>
