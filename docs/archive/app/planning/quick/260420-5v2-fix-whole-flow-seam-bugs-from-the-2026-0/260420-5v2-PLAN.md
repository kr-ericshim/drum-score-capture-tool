**files**

- `desktop/renderer-v2/src/features/source/SourceScreen.js`

- `desktop/renderer-v2/src/features/archive/ArchiveModal.js`
- `backend/app/schemas.py`
- `backend/app/main.py`

**action**
- 새 YouTube prepare 시작, registry 재진입, archive 재오픈 모두 하나의 “새 source intent”로 취급해서 기존 preview/export/review/job polling을 끊고 downstream state를 즉시 비운다.
- prepared YouTube source를 registry나 archive에서 다시 열 때 `youtube` identity와 display name이 local file identity로 붕괴되지 않도록 source metadata를 함께 전달한다.
- archive는 단순 PDF/folder browser에서 끝나지 않고, 가능한 항목은 source/ROI 흐름으로 다시 불러올 수 있게 최소 재진입 경로를 추가한다.

**verify**
- old source/export/review 상태가 YouTube prepare 시작 직후 바로 닫힌다.
- prepared YouTube registry/archive 재진입 후에도 `archiveSourceKind=youtube` / canonical key / display name이 유지된다.
- archive detail에서 reopen action이 실제 source load 흐름으로 이어진다.

**done**
- source 관련 재진입/전환이 항상 새 세션으로 시작되고, old session 결과가 UI에 남아 있지 않는다.

## Task 2. ROI, export, review 계약과 stale-session race 고정

**files**
- `desktop/renderer-v2/src/app/App.js`
- `desktop/renderer-v2/src/app/session/selectors.js`
- `desktop/renderer-v2/src/app/session/runtimeSafety.js`
- `desktop/renderer-v2/src/features/review/ReviewScreen.js`
- `desktop/renderer-v2/src/lib/api.js`

**action**
- same-frame ROI 재적용도 frame/candidate 전환과 동일하게 downstream export/review state를 relock 하도록 만든다.
- draft ROI가 applied ROI와 다르면 export/review step을 다시 잠그고 stale applied ROI로 job이 생성되지 않게 한다.
- export format 변경은 기존 completed/running export result를 무효화해서 review apply가 stale format/job contract 위에서 실행되지 않게 만든다.
- review apply는 page-mode / capture-mode를 구분해서 backend에 맞는 payload를 보내고, stale session 응답은 source 전환 후 state를 덮지 못하게 막는다.

**verify**
- same-frame ROI reapply 후 review/export가 다시 잠긴다.
- draft ROI pending 상태에서는 export/review 진입과 실행이 막힌다.
- empty format 상태로 review apply가 불가능하다.
- page-mode review export가 실제 `keep_images` 경로를 타고, stale review/apply 응답이 새 source session을 덮지 못한다.

**done**
- renderer-v2가 보여주는 ROI/export/review 의미와 실제 backend payload 계약이 다시 일치한다.
