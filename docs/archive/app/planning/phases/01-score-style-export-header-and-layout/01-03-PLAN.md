## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| modal input state -> confirmed export payload | UI orchestration can submit stale metadata or silently drop edits if confirm/close semantics are weak |
| overlay UI -> user interpretation of the export step | adding the modal can accidentally turn the export screen into a generic settings form and bury the preview workbench |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | T | `desktop/renderer-v2/src/app/App.js` modal orchestration | mitigate | Require explicit confirm before payload creation, track dirty-close separately, and extend runtime tests so `createJob(...)` never sees stale metadata after the modal interaction. |
| T-03-02 | D | `desktop/renderer-v2/src/features/export/ExportScreen.js` workbench layout | mitigate | Keep the existing `.export-workbench` structure, add the modal as an overlay instead of an inline form, and lock the preview-first contract in screen-level tests so the export step cannot regress into a long settings slab. |
</threat_model>
